Construir un agente en una empresa no es elegir "un framework". Es componer **media docena de piezas** —modelo, orquestación, herramientas, conocimiento, memoria, seguridad y operación— y decidir cuáles construyes, cuáles compras y cómo se conectan. Esta página es el mapa; el resto de la guía profundiza en cada zona.

<Callout type="info" title="Si vienes de ADK + AI Gateway + Bedrock">
Tu stack ya cubre tres capas clave: **orquestación** (ADK), **acceso a modelos** (gateway) y **modelos** (Bedrock). Lo que esta guía agrega es el resto del mapa —RAG, MCP, A2A, runtime gestionado, evaluación y gobierno— y cómo encaja con lo que ya tienes. Ve directo a la [arquitectura de referencia de tu stack](/guia/arquitectura-adk-gateway-bedrock) si quieres el resultado final.
</Callout>

## Cinco niveles de abstracción

La primera decisión no es *qué* framework, sino **cuánto quieres construir**. Piensa en una escalera: cada peldaño reduce el código propio y aumenta la dependencia del proveedor.

<Diagram id="panorama-caminos" height={640} />

En la práctica, la combinación ganadora en empresas es **framework open source (nivel 2) sobre plataforma gestionada (nivel 4)**: mantienes el código de negocio portable y testeable, y delegas la operación (aislamiento, identidad, memoria, escalado) en el proveedor cloud donde ya están tus datos.

<Callout type="warning" title="Bedrock Agents (Classic) ya no acepta clientes nuevos">
AWS renombró el servicio original a **Bedrock Agents Classic** y recomienda **Bedrock AgentCore** para proyectos nuevos. Muchos tutoriales de 2024–2025 todavía usan el clásico: evítalos como punto de partida.
</Callout>

## Protocolos: el gran cambio de 2025–2026

Hace dos años cada framework tenía su propia forma de conectar herramientas y agentes. Hoy hay **estándares abiertos bajo gobernanza neutral**: en diciembre de 2025 la Linux Foundation creó la **Agentic AI Foundation (AAIF)**, que hoy alberga MCP, AGENTS.md, goose, A2A (desde agosto de 2026) y Agent Skills (desde octubre de 2026).

| Protocolo | Conecta | Estado (oct. 2026) |
|---|---|---|
| [MCP](/guia/mcp) | Agente ↔ herramientas y datos | Spec `2026-07-28`: **stateless**, MRTR, extensión Tasks, OAuth 2.1 |
| [A2A](/guia/a2a) | Agente ↔ agente | v1.0.1; Agent Cards firmadas, gRPC/JSON-RPC/REST |
| AG-UI | Agente ↔ interfaz de usuario | Protocolo de eventos (CopilotKit) |
| Agent Skills | Conocimiento procedimental empaquetado | Estándar abierto, adoptado por 70+ plataformas |
| AGENTS.md | Instrucciones para agentes de código | "README para agentes", 60k+ repos |

<Callout type="tip">
Diseña tus integraciones **con MCP desde el día uno**, aunque hoy uses un solo framework: tus herramientas quedan reutilizables por cualquier agente, IDE o plataforma, y puedes gobernarlas centralmente con un tool gateway.
</Callout>

## Qué cambió en 2026 (y desactualiza tutoriales)

<Steps>

1. **MCP es stateless** desde la spec `2026-07-28`: desaparece el handshake `initialize` y las sesiones del protocolo; sampling y roots quedan deprecados. Mucho material todavía describe la versión 2025.
2. **A2A llegó a v1.0** (marzo de 2026) con cambios incompatibles respecto de 0.3 (operaciones en PascalCase, `Part` unificado).
3. **Renombres masivos**: Vertex AI → Gemini Enterprise Agent Platform (Agent Engine → Agent Runtime); Azure AI Foundry → Microsoft Foundry; Cloudflare AutoRAG → AI Search; LangGraph Platform → LangSmith Deployment.
4. **ADK 2.0** (GA mayo de 2026 en Python) introduce workflows en grafo que reemplazan a los agentes de workflow clásicos; las docs se mudaron a **adk.dev**.
5. **Los "harness" se volvieron una categoría**: agentes preconfigurados con compactación y planificación (Claude Agent SDK, Strands Harness, AgentCore Harness, Microsoft Harness Agent).
6. **Seguridad de la cadena de suministro**: las versiones 1.82.7 y 1.82.8 de LiteLLM en PyPI fueron comprometidas (marzo de 2026). Fija versiones (`litellm>=1.84`) y verifica dependencias.

</Steps>

## Cómo decidir sin perderse

<KeyPoints title="Heurísticas que funcionan">

- **Empieza simple**: una llamada bien diseñada → workflow → agente → multiagente. Sube solo cuando una medición lo justifique.
- **Corre donde están tus datos**: si tu información vive en AWS, el runtime y el RAG gestionado de AWS reducen latencia, costo y fricción de seguridad.
- **Framework portable + protocolos estándar** (MCP, A2A) minimizan el lock-in más que cualquier elección de proveedor.
- **Centraliza el acceso a modelos** con un gateway desde el principio: presupuesto, auditoría y fallback son difíciles de agregar después.
- **Evals y trazas no son opcionales**: sin ellos no sabrás si un cambio de prompt, modelo o framework mejoró o empeoró el sistema.

</KeyPoints>
